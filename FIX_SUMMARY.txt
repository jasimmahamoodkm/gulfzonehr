EMPLOYEE AUTO-CREATION SYSTEM - FIX SUMMARY
================================================================================

ISSUE RESOLVED:
  Default Employee role was not being assigned to newly created employees,
  preventing them from logging in and accessing the employee dashboard.

================================================================================
ROOT CAUSES (2 CRITICAL BUGS)
================================================================================

BUG #1: Incorrect Database Column Name
────────────────────────────────────────
  Location: src/app/api/admin/create-employee/route.ts, line 136

  WRONG CODE:
    .eq('role_name', 'Employee')

  CORRECT CODE:
    .eq('name', 'Employee')

  Why: The roles table has a column named 'name', not 'role_name'
       This caused the role lookup to fail silently (returning null)

  Reference: migrations/003_create_rbac_tables.sql line 8
    CREATE TABLE roles (
      ...
      name VARCHAR NOT NULL UNIQUE,  ← The actual column
      ...
    )

BUG #2: Missing Required Database Field
─────────────────────────────────────────
  Location: src/app/api/admin/create-employee/route.ts, line 157-161

  WRONG CODE:
    const { error: roleError } = await supabaseAdmin
      .from('user_roles')
      .insert({
        user_id: userId,
        role_id: roleData.id,
        // Missing: company_id
      });

  CORRECT CODE:
    const { error: roleError } = await supabaseAdmin
      .from('user_roles')
      .insert({
        user_id: userId,
        role_id: roleData.id,
        company_id: payload.company_id,  ← Added
      });

  Why: The user_roles table requires company_id (NOT NULL constraint)
       The UNIQUE constraint is on (user_id, role_id, company_id)
       Without it, the insert fails

  Reference: migrations/003_create_rbac_tables.sql line 34-41
    CREATE TABLE user_roles (
      ...
      company_id UUID NOT NULL REFERENCES companies(id),  ← REQUIRED
      ...
      UNIQUE(user_id, role_id, company_id)  ← All 3 required
    )
